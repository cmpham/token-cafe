## Exercised path

Live process identity → session-file collector → transcript reader → Rust desktop
bridge → authenticated HTTP over ADB reverse → Android polling → JNI → shared
Rust scene → Android bitmap → actual touch events and displayed-text assertions.

The runner checks rendered screen pixels against the shipped bitmap alphabet,
reads connection status through Android accessibility, and verifies collector
state through the bridge response. Native scene state is not queried directly.
Only synthetic demo views and the controlled session's footer are saved.

## Repeat

Boot an Android emulator and install the debug APK, then run from the repository
root with Rust, Android Platform Tools and Python with Pillow available:

```sh
cargo build --locked --no-default-features --example android_bridge
python3 tools/test_android_e2e.py --serial emulator-5554
```

Use your emulator's actual serial. The runner also accepts `--adb`, `--bridge`
and `--output`. Port 38417 must be free. It manages its bridge, temporary files,
test process and forwarding; the emulator remains available to the caller.

Initial runner iterations corrected an accessibility selector, generic OCR
misreading the pixel font, assumptions about hard-wrapped task pages, and
selection during resolution notices/rotation. The final full run passed all
checks; these corrections changed the test runner rather than the application.

## Limits

The controlled process supplies synthetic Claude-compatible files; this does not
validate a real Claude/Codex model session or provider invocation. Physical USB,
x86-64 runtime, API 26 runtime, 16 KiB runtime, battery/thermal behavior and
screen-reader session navigation remain unverified. Permission-alert rendering
was checked; remote approval execution is outside this read-only app's scope.
